# Core functions

Use an independent baseline for each case. See the [front-end routes](../../app/frontend/src/javascript/router.js) for nested paths such as `/dashboard/reservations`.

## Accounts, members, and permissions

| ID · Case | Tag | Automatable | Preconditions | Steps | Expected results |
| --- | --- | --- | --- | --- | --- |
| ACC-01 · Register and confirm an account | `smoke` | Yes | Use FabManager authentication. Enable public registration. Start MailCatcher. Use a new test address. | 1. Select “Sign Up” as a guest.<br>2. Submit the registration form.<br>3. Open the confirmation link in MailCatcher.<br>4. Sign in.<br>5. Disable public registration.<br>6. Open the sign-in page again. | The confirmation email arrives. The confirmed account can sign in. “Sign Up” is absent when registration is disabled. |
| ACC-02 · Reset a password | `full` | Yes | Use a local member account, MailCatcher, and valid and expired reset links. | 1. Request a reset link from the sign-in page.<br>2. Submit a weak password with the valid link.<br>3. Submit a valid new password.<br>4. Try to sign in with the old password.<br>5. Open the expired link. | A clear error appears for a weak password, with no duplicate colon. Only the new password works. An invalid or expired link shows a clear error, not HTTP 500. |
| ACC-03 · Delete an account | `full` | Yes | Use three separate member accounts. Give the first a future reservation and the second an active subscription. Use the QA Delete account as the control. | 1. Try to delete each account.<br>2. Reload the page.<br>3. Check the accounts and related records. | The first two attempts show an error in the selected language. Both accounts and their records remain. The control account is deleted. |
| ADM-01 · Export members and edit a member | `smoke` | Yes | Use an administrator, a member, a test tag, a small image, and Sidekiq. | 1. Export the member list from `/admin/members`.<br>2. Download the XLSX file.<br>3. Add a tag to the member.<br>4. Replace the member’s profile image.<br>5. Reload the page. | The XLSX file opens. A message in the selected language confirms the tag change. The new image stays visible. |
| ADM-02 · Renew, extend, and cancel a subscription | `full` | Yes | Use an administrator, a recently purchased renewable subscription, and MailCatcher. | 1. Renew the subscription from the member edit page.<br>2. Cancel that subscription without reloading.<br>3. Give a second test subscription a free extension.<br>4. Compare the date in the email with the date on the page. | The app cancels the current subscription. The invoice list updates. The extension dates agree. The app sends the email only after the extension is available in the app. |
| ADM-03 · Create staff accounts and change roles | `full` | Yes | Use separate administrator and manager sessions. Prepare unused and used test email addresses. | 1. As administrator, create an administrator account.<br>2. Create a manager account.<br>3. Open “Change role” for a test user.<br>4. Select “Manager”.<br>5. Try to reuse an email address.<br>6. As manager, edit a member.<br>7. Check access to staff accounts, role changes, and member deletion. | Allowed role changes succeed. A duplicate address shows a clear error. The manager can edit a member and see their credits without an unhandled HTTP 403. The manager cannot delete members, change roles, or edit staff accounts. |
| ADM-04 · Import members with valid and invalid rows | `full` | Yes | Use an administrator. Use the template at `/admin/members/import` to make a synthetic CSV with a UTF-8 BOM, dates, and empty cells. | 1. Check that the instructions list `username`.<br>2. Import rows that create members and update members by email.<br>3. Open the results.<br>4. Repeat with unknown tags, unknown trainings, invalid dates, invalid CSV, and a file type the app does not accept. | Rows that match by email keep the member ID. Empty cells do not erase existing values. The results identify invalid rows. They still open, the job ends, and existing birth dates remain. A rejected upload shows a message. |
| ADM-05 · Check access by role | `full` | Yes | Use an administrator, a manager, a partner, and two test members. Set one member’s profile to private. | 1. Check the member list, import page, and administration menus with each role.<br>2. As the second member, check invoices, wallet entries, and reservations.<br>3. As partner, search for the member with a private profile. | Members see only their own transactions. Managers cannot import members or access settings or accounting closure. Partner search results do not expose private profile data. |

## Dashboard, family, and supporting documents

| ID · Case | Tag | Automatable | Preconditions | Steps | Expected results |
| --- | --- | --- | --- | --- | --- |
| DASH-01 · Check the dashboard and public profile | `smoke` | Yes | Use a member with a published project, an order, and training and reservation records. | 1. Reload `/dashboard/reservations`.<br>2. Open the member profile.<br>3. Check the author on a project card.<br>4. Check the prompts in the order and prepaid pack filters.<br>5. Disable the store.<br>6. Return to the dashboard. | The dashboard loads after reload. The author label and filter prompts use the selected language. A private author has no broken link. The “My orders” tab is absent when the store is disabled. The reservation list has no cancellation control. |
| DASH-02 · Change an email address | `full` | Yes | Use local authentication and a member account. Prepare a valid new address. | 1. Change the email address at `/dashboard/profile`.<br>2. Reload the page.<br>3. Sign out.<br>4. Sign in with the new address. | The new address stays in the profile and works at sign-in. The app does not ask for confirmation when `reconfirmable = false`. |
| FAM-01 · Set up a family account and upload documents | `full` | Yes | Use an administrator, a member, MailCatcher, and a synthetic PDF. Enable family accounts and account validation. | 1. Use a setting label to change its switch.<br>2. Create document requests for children and adults.<br>3. Assign the requests to groups.<br>4. Add a child.<br>5. Upload and then replace each PDF.<br>6. Change the child’s phone number.<br>7. Download each PDF as member and as administrator.<br>8. Try two birth dates: exactly 18 years ago and one day later.<br>9. Search for the child’s full name in the member list.<br>10. Apply the filter for accounts that are not validated. | The label changes its switch. Both roles can read the PDFs. The email agrees with the changes. The app rejects a person aged exactly 18 and accepts the younger child. The name search finds the parent. The validation filter applies only to adult accounts. |
| FAM-02 · Refuse supporting documents once | `full` | Yes | Use an administrator, MailCatcher, and a member whose account is not validated and who uploaded the required files. | 1. Open “Supporting documents” on the member’s record.<br>2. Try to submit the empty refusal form.<br>3. Select a document type.<br>4. Enter a reason.<br>5. Submit the refusal.<br>6. Open the dialog again without reloading. | The app prevents empty submissions. Only the email to the member and the copy to the administrator from this submission arrive. |
| FAM-03 · Book a family event after validation | `full` | Yes | Use a family event with eight places and required validation, two children who are not validated, and a separate €5 event. Add funds to the wallet. | 1. Try to book as an adult who is not validated.<br>2. Try to select a child whose documents are not yet approved.<br>3. Approve the documents as administrator.<br>4. Buy one child ticket.<br>5. Open the participant selector again.<br>6. Repeat with one place left.<br>7. Pay for the €5 event from the wallet. | Before validation, a message explains the block. After validation, one ticket uses one place. The same child cannot be selected again. The quantity cannot exceed the remaining places. When the last place is sold, the event shows that it is full. The app debits €5 and sends reservation and invoice emails. |
| FAM-04 · Reject zero tickets and remove a child | `full` | Yes | Use a free family event and a member with children. Use a separate reservation for a child that the app allows the member to delete. | 1. Select “Book” on the free event.<br>2. Change the ticket quantity from one to zero.<br>3. Remove all participants.<br>4. Try to confirm.<br>5. Delete the child in the separate test.<br>6. Open the child’s old reservation. | The app does not confirm or create a zero-ticket reservation. The old participant list no longer shows the deleted child’s name. |

## Calendar, reservations, events, and training

| ID · Case | Tag | Automatable | Preconditions | Steps | Expected results |
| --- | --- | --- | --- | --- | --- |
| CAL-01 · Check the calendar and export time slots | `smoke` | Yes | Use a member with a training reservation, an administrator, and Sidekiq. | 1. Open the booked training at `/calendar`.<br>2. Export available time slots from `/admin/calendar`.<br>3. Download the file.<br>4. Open the file. | The title has no extra apostrophe. The app supplies an XLSX file and does not show raw JSON. |
| CAL-02 · Synchronize an iCalendar source | `full` | Yes | Use an administrator, a local iCalendar server, Sidekiq, and the scheduler. | 1. At `/admin/calendar/icalendar`, open “New ICS import”.<br>2. Add a source.<br>3. Sync a feed with events.<br>4. Sync an updated feed.<br>5. Return HTTP 503 on the next sync.<br>6. Sync a valid empty feed.<br>7. Restore the feed with events.<br>8. Delete the source.<br>9. Check the calendar after each change. | Event text is readable. The update replaces the source data. HTTP 503 preserves existing events. The empty feed and the source deletion each remove the events from that source. |
| BOOK-01 · Resume a reservation and cancel without a wallet refund | `smoke` | Yes | Use future slots for an unrestricted machine, a space, and a training. Fund the member wallet. Enable cancellation. Start MailCatcher. | 1. As a guest, sign in from the space or training reservation page.<br>2. Book the unrestricted machine with the wallet.<br>3. Record the debit.<br>4. Cancel as the member.<br>5. Create a second reservation.<br>6. Cancel it as administrator.<br>7. Open the administrator’s cancellation email. | Sign-in returns to the reservation page. Cancellation updates the reservation and releases the slot. It does not refund the wallet. The email distinguishes the member from the administrator who canceled. |
| BOOK-02 · Check deadlines, time windows, and plan limits | `full` | Yes | Use a time zone with daylight saving time. Enable reservation and cancellation deadlines. Set separate machine, category, and other applicable plan limits. | 1. Compare member and staff access before and after each deadline.<br>2. Test cancellation when disabled and with empty, zero, and boundary values.<br>3. Try to save a window that starts at or after its end.<br>4. Compare reservations on both sides of local midnight.<br>5. Test a window across a daylight saving time change. | The app applies valid time windows. It rejects invalid windows. Limits use the local day. Staff exemptions apply where configured. |
| BOOK-03 · Move reservations and check slot restrictions | `full` | Yes | Use a member with a reservation. Enable overlap prevention. Prepare open, full, past, and locked slots. | 1. From the administration page, try to move the reservation to each target, including a slot for a different resource.<br>2. As the member, try to book a partly overlapping event.<br>3. Try to book a locked slot.<br>4. Cancel the overlapping reservation.<br>5. Try to book the event again. | A move cannot target full or past slots or slots for another resource. Members cannot book locked slots or overlap an active reservation. Canceled reservations do not block bookings. |
| BOOK-04 · Book for a member and offer a slot | `full` | Yes | Use an administrator, a manager, and two members with different rates. One member has no training approval. Use an available machine. | 1. On the machine reservation page, select the first member.<br>2. Add a slot.<br>3. Select the second member.<br>4. Check the price.<br>5. Use the cart control to offer the slot.<br>6. As manager, check which accounts you can select. | The price matches the selected member. The offer applies only to that member. Administrators and managers can book for members without training approval. Managers cannot book for administrators or managers. |
| EVT-01 · Create, change, and cancel an event reservation | `full` | Yes | Use an administrator and a member. Set standard and reduced ticket prices, capacity, and open registration. | 1. Create an event at `/admin/events`.<br>2. Edit the event.<br>3. As a member, pre-register.<br>4. Pay for the tickets.<br>5. As administrator, check the attendee list.<br>6. Change a reservation with both ticket types.<br>7. Cancel or delete the event. | The pre-registration shows that it is paid. The change keeps both ticket types. The event is not marked full if places remain. The canceled event is absent from upcoming events. |
| TRN-01 · Grant, remove, and validate training approval | `smoke` | Yes | Use a machine that requires `QA Training`, a member without approval, and an attended training reservation. | 1. As administrator, grant approval on the member page.<br>2. Check machine access.<br>3. Remove approval.<br>4. Check access again.<br>5. Repeat as manager.<br>6. Submit bulk validation from training monitoring.<br>7. Submit it again. | Approval enables machine reservations. Removing approval blocks them. Repeating validation creates no duplicate approval or notification. |
| TRN-02 · Automatically cancel a training | `full` | Yes | Use a training below its attendance threshold, a restricted machine, and MailCatcher. Use separate tests with wallet payment, percentage and fixed discounts, and a subscription credit. | 1. Record the amount paid or credits used.<br>2. Run `TrainingAutoCancelWorker`.<br>3. Check the wallet and any credit note.<br>4. Check the messages and credits.<br>5. Open the machine reservation page. | A wallet refund equals the actual debit, to the cent. A training paid with a credit causes no wallet refund, no credit note, and no return of the credit. The member gets the correct email. The canceled training is no longer pending on the reservation page. |
| TRN-03 · Expire training approval and notify when a child turns 18 | `full` | Yes | Use a trained member, a child about to turn 18, a test inbox, and a local clock you can control. | 1. Run `TrainingAuthorizationWorker` for expired approval.<br>2. Test manual removal separately.<br>3. After midnight in Paris, run `ChildAgeWorker` for a child who just turned 18. | The member loses booking access. The email uses the actual training date. The age notice uses the local date and shows the 18th birthday, not the birth date. |
